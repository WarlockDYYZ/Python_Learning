一、ETL 入库脚本：多源抽取、清洗与批量入库

    1.1 ETL 架构设计原则
        针对「用户行为分析系统」的业务场景，采用增量抽取 + 批量加载 + 断点续传的生产级架构，核心流程：
            1. 抽取（Extract）：从两类数据源拉取数据：
                - 业务关系型数据库源：MySQL（存储用户基础行为）、PostgreSQL（存储用户标签数据）
                - 第三方 / 内部 API 源：用户行为上报 API、用户画像标签 API
            2. 清洗（Transform）：校验数据格式、脱敏敏感字段、去重、补全缺失字段、统一字段映射
            3. 加载（Load）：批量 / 增量写入分析库的user_behaviors、user_tags表，保障入库性能与数据一致性


    1.2 多数据库源连接（生产级方案）
        1.2.1 通用连接池封装（兼容 MySQL/PostgreSQL）
            禁止使用裸数据库连接，基于 SQLAlchemy 封装支持同步 / 异步的多源连接池，复用项目原有配置体系，从.env读取数据源配置，避免硬编码：
                db_pool.py

        1.2.2 支持的数据库连接示例
            数据库类型	        连接 URL 格式	                                                    驱动依赖
            MySQL（同步）	        mysql+pymysql://user:password@host:port/dbname?charset=utf8mb4	pymysql
            MySQL（异步）	        mysql+asyncmy://user:password@host:port/dbname?charset=utf8mb4	asyncmy
            PostgreSQL（同步）	postgresql://user:password@host:port/dbname	                    psycopg2-binary
            PostgreSQL（异步）	postgresql+asyncpg://user:password@host:port/dbname	            asyncpg

        1.2.3 ETL 数据源配置初始化
            在app/etl/__init__.py中加载多源库连接，同时遵守最小权限原则：ETL 数据库账号仅赋予SELECT权限，目标分析库账号仅赋予INSERT/UPDATE权限：
                __init__.py


    1.3 API 数据源抽取（生产级方案）
        1.3.1 通用 API 调用封装（支持鉴权、分页、重试、限流）
            用httpx实现异步 API 调用，封装签名鉴权、分页拉取、失败重试、流量控制逻辑，适配第三方用户行为 API、内部用户画像 API 的抽取需求：
                api_client.py
