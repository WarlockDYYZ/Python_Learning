一、MySQL + pymysql 基础架构与工作原理

    1.1 MySQL 核心架构解析
        MySQL 采用经典的客户端 - 服务器 (C/S) 架构，其核心设计理念是 "分层解耦、职责单一"。整个架构从上到下分为四层，每一层都有明确的职责边界：
            - 连接层（Connector）是客户端访问 MySQL 的第一道关卡，负责处理客户端连接、身份认证、权限校验和会话管理。
                    当客户端发起连接请求时，连接器首先进行 TCP 三次握手建立连接，然后验证用户名、密码和主机地址。
                    认证通过后，连接器会从mysql.user等系统表中读取该用户的所有权限，这些权限信息在整个连接生命周期内保持不变，
                    即使管理员后续修改了用户权限，也不会影响已建立的连接。
            - 服务层（Server Layer）是 MySQL 的 "大脑"，负责 SQL 语句的完整处理流程，包括查询缓存、解析器、优化器和执行器。
                    这一层的核心流程分为五步：
                        解析→授权→优化→执行→日志
                        - 解析器负责拆解 SQL 语法，将其转换为内部可识别的结构
                        - 优化器基于成本模型（CBO）选择最优执行计划，计算维度包括 IO 成本（默认 16KB 数据页的 IO 成本为 1.0）和 CPU 成本（默认读取一行数据的 CPU 成本为 0.2）
                        - 执行器负责调用存储引擎的 API 执行具体操作
            - 存储引擎层（Storage Engine Layer）负责数据的存储与提取，采用插件式架构设计。
                    MySQL 5.5 版本之后默认使用 InnoDB 引擎，它支持事务、行级锁、MVCC（多版本并发控制）等高级特性。
                    需要特别注意的是，MySQL 并非天生自带 InnoDB，而是实现了 InnoDB、MyISAM 等多种存储引擎的接口，开发者可以根据需求选择合适的引擎。
            - 文件系统层（File System Layer）负责与底层操作系统的文件系统交互，处理数据的物理存储和持久化。

    1.2 pymysql 工作原理与特性
        pymysql 是一个纯 Python 实现的 MySQL 客户端库，无需编译依赖即可连接 MySQL 数据库。
                它通过提供类似 DB-API 的接口，支持建立连接、创建游标、执行 SQL 查询、数据操作及事务管理等功能。

        pymysql 的核心特性包括：
            - 纯 Python 实现：无 C 依赖，跨平台兼容，支持 Python 3.6 + 所有版本和 MySQL 5.5+/8.0 + 全版本
            - 完整的 CRUD 支持：原生支持增删改查操作，适用于常规业务数据处理
            - 事务管理：支持提交、回滚、保存点等事务控制功能，特别适合金融、订单等强一致性要求的场景
            - 连接池适配：兼容 DBUtils 等连接池实现，适合高并发 Web 服务
            - 数据类型自动映射：自动转换 Python 与 MySQL 数据类型，简化数据处理流程

        pymysql 的工作流程遵循标准的数据库操作模式：
            用户调用 → 建立连接 → 创建游标 → 执行 SQL → 获取结果 → 提交 / 回滚 → 关闭游标 → 关闭连接。
            这种清晰的流程设计使得开发者能够轻松理解和掌握数据库操作的每一个环节。

    1.3 Python 操作 MySQL 的技术栈架构
        Python 操作 MySQL 的完整技术栈呈现清晰的分层结构：
            - 应用层包括各种 Python 应用场景，如脚本开发、Flask/Django/FastAPI 等 Web 框架、数据分析脚本、自动化运维工具等。
                    这些应用通过调用底层的数据库驱动与 MySQL 交互。
            - 驱动层提供不同的数据库连接方式：
                - PyMySQL：纯 Python 实现，轻量易用，是目前最流行的选择
                - mysql-connector-python：Oracle 官方驱动，稳定可靠但需要 C 依赖
                - SQLAlchemy：强大的 ORM 框架，通过抽象底层差异提供统一接口
            - 协议层负责 TCP/IP 连接、认证和数据传输，遵循 MySQL 协议规范。
            - 存储层即 MySQL 服务器本身，负责库、表、行、索引、事务日志等数据的存储和管理。

        这种分层架构的优势在于高内聚低耦合，每一层都可以独立发展和优化，同时通过标准化接口进行协作。
        例如，开发者可以在不改变业务逻辑的情况下，从 PyMySQL 切换到 mysql-connector-python，或者从原生 SQL 切换到 ORM 操作。
