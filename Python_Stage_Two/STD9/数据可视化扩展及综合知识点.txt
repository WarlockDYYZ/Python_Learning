数据可视化综合知识点

一、Python 数据可视化生态系统概览

    1.1 主要可视化库对比分析
        Python 拥有丰富的数据可视化生态系统，每个库都有其独特的设计理念和适用场景。
            Matplotlib：基础绘图的基石
                Matplotlib 是 Python 数据可视化的基础库。它采用面向对象的设计理念，提供了极其灵活的绘图接口，几乎可以创建任何类型的静态图表。
                Matplotlib 的最大优势在于其高度可定制性，用户可以精确控制图表的每个元素，这使得它特别适合需要出版质量图表的科研场景。
                Matplotlib 也存在一些局限性。它的 API 相对复杂，即使创建简单图表也需要编写较多代码。默认的图表样式相对传统，缺乏现代感。
                对于大规模数据集（100,000 + 数据点），Matplotlib 的渲染速度会明显下降。
            Seaborn：统计可视化的优雅解决方案
                Seaborn 构建在 Matplotlib 之上，专注于统计数据的可视化。
                它提供了更高级的接口和更美观的默认样式，特别适合探索性数据分析（EDA）。
                Seaborn 的核心优势包括：与 Pandas DataFrame 的完美集成，可以直接使用数据框的列名创建复杂统计图表；
                内置了许多统计模型的可视化功能，如回归分析、相关性热力图等；提供了丰富的调色板和主题选项，使图表更加美观专业。
                Seaborn 的学习曲线相对平缓，适合快速创建美观的统计图表。
                但它也有局限性：由于基于 Matplotlib，某些高级定制仍需使用 Matplotlib 函数；不支持交互式图表，生成的都是静态图像。
            Plotly：交互式可视化的领导者
                Plotly 是一个现代化的交互式可视化库，支持多种编程语言。
                它的最大特点是原生支持交互功能，用户可以通过鼠标进行缩放、平移、悬停查看数据点详情等操作。
                Plotly 支持 3D 图表、地图可视化和动画效果，特别适合制作仪表板和 Web 应用。
                Plotly Express 作为 Plotly 的高级接口，提供了简洁一致的 API，类似 Seaborn 但产生交互式输出。
                大多数图表只需要一次函数调用即可创建，大大简化了使用流程。
                Plotly 生成的图表可以导出为 HTML 格式，非常适合在网页中展示。
                但需要注意的是，对于超大规模数据集，Plotly 在浏览器中的渲染速度可能会受到影响。
            Bokeh：高性能 Web 可视化
                Bokeh 是一个用于创建交互式 Web 图表的 Python 库。
                它专注于高性能的 Web 可视化，特别擅长处理大型数据集（百万级数据点）。
                Bokeh 提供了丰富的图表类型和交互功能，可以创建出高度可定制的交互式图表。
                Bokeh 的独特优势在于其流式数据处理能力和对大型数据集的高效渲染。它支持 WebSocket 实时更新，可以创建真正的实时仪表板。
                Bokeh 的图表可以直接在 Web 浏览器中显示，支持与用户的深度交互。但 Bokeh 的学习曲线较陡峭，需要更多的配置工作。
            Altair：声明式统计可视化
                Altair 是一个基于 Vega-Lite 规范的声明式统计可视化库。
                它的设计理念是让用户专注于 "做什么" 而不是 "怎么做"，通过简洁的语法实现复杂的可视化。
                Altair 的核心特点包括：基于 "图形语法" 的声明式语法，代码简洁优雅；
                        内置了强大的统计变换功能，可以直接在图表规范中进行数据处理；默认样式美观现代，符合现代设计美学。
                Altair 的优势在于其语法的简洁性和统计功能的强大性。它特别适合快速探索数据和创建统计图表。
                Altair 也有一些限制：基于 JavaScript 渲染，对大数据集（超过 100,000 点）可能存在性能问题；
                某些高级定制需要深入了解 Vega-Lite 规范。

    1.2 各库适用场景与学习难度
        各库的适用场景, 实际用到了自己查嘛，Matplotlib 和 Seaborn 基本就可以处理大部分场景。
            已有的 Python 和 Matplotlib、Seaborn基础，各库的学习难度排序如下：
                - Plotly Express（容易）：API 设计简洁一致，类似 Seaborn 但支持交互
                - Altair（中等）：声明式语法需要适应，需要理解数据类型系统
                - Plotly Graph Objects（中等偏难）：功能强大但 API 复杂，需要较多学习
                - Bokeh（较难）：概念较多，需要理解模型 - 视图架构，配置相对复杂
                - Matplotlib（最难精通）：虽然基础概念容易，但高级定制需要深入学习

            Dash 是 Plotly 开发的 Web 应用框架，允许用户使用纯 Python 创建交互式 Web 应用。这为数据可视化提供了全新的可能性。

            一个简单的 Dash 应用示例：
                plotly_dash.py

                dash.Dash(__name__)：这是创建 Dash 应用的实例。它相当于给的网页应用搭建了一个最基础的骨架。

                px.data.gapminder()：这里直接调用了 Plotly Express (px) 内置的一个经典数据集（全球各国的人口、预期寿命等数据）。
                .query("country=='Canada'") 则是像写 SQL 一样，从这个庞大的数据表中精准筛选出了“加拿大”的数据行，并赋值给 df（DataFrame）。
                补充：
                    .query() 是 Python 数据分析神器 Pandas（DataFrame）中一个非常强大且优雅的数据筛选函数。
                    .query() 允许直接传入一个字符串形式的条件表达式，来过滤 DataFrame 中的行。
                    它的语法非常接近自然语言或者数据库里的 SQL 语句，读起来特别顺畅。
                    "country=='Canada'" 的意思就是：找出 country（国家）这一列的值完全等于 'Canada'（加拿大）的所有记录。

                    与传统方法相比：
                        # 传统写法（实现同样的筛选，通常需要使用“布尔索引”，比较啰嗦，符号多容易眼花）
                        # 先加载一次数据
                        full_df = px.data.gapminder()
                        # 再对已经加载好的数据进行筛选
                        df = full_df[full_df['country'] == 'Canada']

                        # .query() 写法（极其简洁、直观）
                        df = px.data.gapminder().query("country == 'Canada'")
                    px.data.gapminder() 的作用是从 Plotly 的内置库里加载一份完整的全球数据集。

                    还可以使用复杂的逻辑：
                        # 使用 & 表示“并且”，| 表示“或者”
                        filtered_df = df.query("year > 2000 & lifeExp > 80")
                        # !=、not in 和 not 都可以表示非
                        df.query("country != 'Canada'")
                        df.query("country not in ['Canada', 'United States']")
                        df.query("not country == 'Canada'")

                app.layout 决定了网页长什么样，它是由一个个组件像搭积木一样嵌套组成的：
                    - html.Div([...])：这是一个通用的容器，相当于 HTML 里的 <div> 标签，用来包裹页面上的其他元素。
                    - html.H1(...)：在页面上渲染出一个一级标题，显示文字“Canada Life Expectancy Trend”。
                    - dcc.Graph(...)：这是 Dash 专门用来承载 Plotly 交互式图表的核心组件。
                        - id='life-expectancy-chart'：给这个图表起了一个唯一的身份证号，
                                如果以后想通过按钮或滑块来控制这个图表，就需要通过这个 ID 来找到它。
                        - figure=px.line(...)：直接把刚才准备好的加拿大数据 df，用 Plotly Express 画成了一张折线图（x轴是年份，y轴是预期寿命），
                                然后塞进了 dcc.Graph 里进行展示。

                启动服务器
                if __name__ == '__main__':：这是 Python 的标准写法，确保只有当直接运行这个脚本时，下面的代码才会执行。
                app.run(debug=True)：它会启动一个本地服务器，默认端口通常是 8050。
                debug=True 开启了调试模式，它的最大好处是热重载：
                        当修改了代码并保存后，网页会自动刷新更新，不需要手动重启程序，非常适合开发阶段使用。

        2. 处理大规模数据集的策略
            Bokeh 在处理大规模数据集方面表现出色，提供了多种优化策略：

            - WebGL 支持：使用ScatterGL代替Scatter可以显著提升大数据集的性能：
                base_ScatterGL.py

                LinearColorMapper（线性颜色映射器）：它就像一个“翻译官”。
                    把数值 z（比如 0 到 100）交给它，它会按照指定的调色板（代码中用的 Viridis256 一种从紫到黄的科学渐变色），
                    把每个具体的数字精准地翻译成对应的 RGB 颜色。
                    low 和 high 告诉它翻译的数值范围。
                ColumnDataSource（列式数据源）：这是 Bokeh 官方强烈推荐的“标准数据容器”。
                    它把原本独立的 NumPy 数组 x, y, z 打包成一个字典格式。
                    这样做不仅能让 Bokeh 在处理大量数据时跑得更快，还能让你在后面的绘图代码中直接用 'x', 'y', 'z' 这样的字符串来引用数据列。

                'x', 'y', source=source：这里不再直接传 NumPy 数组，而是去 source 这个数据容器里，找名为 'x' 和 'y' 的两列数据作为横纵坐标。
                color={'field': 'z', 'transform': color_mapper}：
                    - 'field': 'z' —— 找准“原材料”
                        含义：在数据容器（ColumnDataSource）里，找到名为 'z' 的那一列数据。
                        作用：它指定了用哪个变量来决定颜色。
                                Bokeh 会提取出这一列里的每一个数值（比如第1个点的 z=10，第2个点的 z=85...），作为后续计算颜色的基础原材料。
                    - 'transform': color_mapper —— 交给“翻译官”
                        含义：把刚才找到的 'z' 的数值，交给对象 color_mapper 去处理。
                        作用：这里的 color_mapper 就是前面定义的 LinearColorMapper。
                                它是一个严格的规则制定者，负责把抽象的数字翻译成具体的 RGB 颜色。
                            - 比如它内部的规则是：数值 0 对应紫色，数值 50 对应绿色，数值 100 对应黄色。
                            - 当 Bokeh 拿到某个点 z=75 时，就会通过这个 transform 自动算出它应该显示为“黄绿色”。

                render_mode='webgl'：scatter 方法不支持这个参数，删掉后图表就能正常渲染了。

                ColorBar：如果没有这根颜色条，看图表的人只能看到五颜六色的点，却不知道什么颜色代表大数值、什么颜色代表小数值。
                    ColorBar 就是把这个“翻译规则”以图例的形式展示出来。
                    - label_standoff=12：刻度数字（标签）与颜色条本体之间的水平间距 12 个像素的距离。
                    - location=(0, 0)：它决定了颜色条的锚点（起点）在哪里。

                p.add_layout(color_bar, 'right')：把这根颜色条像挂件一样，添加到画布 (p) 的右侧。
                    颜色条整体放在了画布的右侧边栏里。此时，location=(0, 0) 指的就是这个右侧边栏的左下角作为起点。

                注意：
                    render_mode='webgl'
                    Bokeh 中，只有 line（折线图）、patch（区块图）等少数几个图形支持 'webgl' 渲染模式，而 scatter 散点图是不支持的。
                    虽然去掉了 WebGL 加速，Bokeh 默认的 HTML5 Canvas 渲染引擎在处理 10 万个数据点时依然非常流畅，完全能够满足需求。
                    如果你未来确实需要用 'webgl' 来绘制超大规模的图表（比如百万级以上），建议改用 p.line() 或者 p.patch() 等方法，它们才支持开启 WebGL 硬件加速。
                    对实例代码散点图需求，直接使用默认配置就是最佳选择！

    2.3 Altair 声明式语法精要
        Altair 采用独特的声明式语法，让用户专注于 “做什么” 而不是 “怎么做”，这种设计理念大大简化了复杂图表的创建过程。

            - 声明式语法的核心概念：
                Altair 的声明式语法基于 “图形语法”（Grammar of Graphics）的理念。
                在 Altair 中，创建图表的过程是声明性的：只需要告诉 Altair 想要展示什么，而不需要详细描述如何绘制。

                基本的 Altair 图表创建遵循以下模式：
                    base_altair.py

                这个简单的例子展示了 Altair 的核心概念：
                    - alt.Chart(data)：指定数据源
                    - .mark_circle()：指定标记类型（圆形）
                    - .encode()：指定数据到视觉属性的映射

            - 统计变换的强大功能
                Altair 内置了强大的统计变换功能，可以直接在图表规范中进行数据处理，无需在 Python 中预先计算。
                    altair_statistical_transformation.py

                    - 数据分箱（Binning）是常用的统计变换之一：
                        alt.Chart(cars).mark_bar().encode(...)
                            使用 cars 汽车数据集, 画 柱状图, 定义 X、Y 轴
                        alt.X('Horsepower').bin()
                            把马力从低到高分成一段一段（比如 50-100，100-150...）,就是直方图
                        y='count()'
                            统计每个马力区间里有多少辆车, 对应柱子的高度
                        补充：
                            alt.X() 作用
                                是的，专门声明 X 轴字段与轴配置，配套还有alt.Y()，用来精细定义坐标轴映射、格式、分箱等属性。
                            .bin() 分组规则
                                无参bin()：Altair 自动根据数据范围、数据量自适应划分区间组数
                                可手动指定：
                                    bin(maxbins=N) 限定最大分组数
                                    bin(step=N) 固定每个区间跨度
                            加 bin 和不加 bin 的区别：
                                不加 bin：以单个唯一马力值为横坐标，一个数值对应一根柱子，数值离散无合并
