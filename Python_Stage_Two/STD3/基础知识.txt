2. 封装基础理论与实践

2.1 封装概念与核心价值
    封装（Encapsulation）是面向对象编程的三大核心特性之一.
    它指的是将数据（属性）和操作数据的方法（行为）捆绑在一个独立的单元（即 "类"）中。
    封装的核心思想是 "隐藏实现细节，暴露访问接口"。

    封装包含两个核心概念：
        - 数据隐藏：保护对象内部状态不被外部直接修改
        - 接口暴露：提供公共方法控制对内部数据的访问

    现实世界的封装类比：汽车是一个封装良好的对象，内部包含复杂的引擎系统、传动装置等（隐藏），
    而接口则是方向盘、油门踏板、刹车等（公开），用户通过接口操作汽车，无需了解内部构造。

    封装的核心价值体现在三个方面：
        数据保护：防止无效或不一致的状态。通过设置访问权限，我们可以控制哪些内容可以被外部访问，哪些内容应该保持私有。
        降低复杂度：使用者只需关注接口，无需了解实现细节。封装使代码更加模块化，提高了代码的可维护性和可复用性。
        提高可维护性：内部实现可自由修改而不影响外部调用。封装使得类的内部实现可以独立于外部接口进行修改，只要接口保持不变，就不会影响到其他代码。

2.2 访问控制机制
    Python 使用命名约定实现访问控制，而不是强制限制。Python 中定义了三种访问级别：
    类型           	前缀  	示例            	可访问性
    公有（Public）   	无   	name          	任意位置可访问
    保护（Protected）	单下划线	_protected_var	约定私有，但可访问
    私有（Private）  	双下划线	__private_var 	类内可访问，外部通过名称修饰访问

    2.2.1 公有成员
        公有成员是 Python 中的默认类型，不需要特殊的修饰符。公有成员可以在类的内部、外部以及子类中直接访问。
            Person.py

    2.2.2 保护成员
        保护成员以单下划线开头（如_var），它是一种弱 "保护" 的指示符。保护成员在类内部和子类中可以直接访问，但在外部使用时会收到警告。
        保护成员的约定意义是：
            - 提示开发者 "这是内部实现，请勿直接使用，因为它可能改变"
            - 在其他模块中不可访问（但在同一模块中仍可访问）
            Animal.py
        还是可以通过 ._name 的方式访问，但会收到 IDE 的警告

    2.2.3 私有成员
        私有成员以双下划线开头（如__var），它通过名称重整（name mangling）机制实现访问限制。
        Python 会自动将__var 重命名为_类名__var（如_BankAccount__balance），外部无法直接访问。

        私有成员的特点：
            - 只能在类的内部访问
            - 外部代码无法直接访问或修改
            - 通过名称重整机制防止子类意外覆盖

    补充：@staticmethod 静态方法
        @staticmethod 装饰器：把方法变成「静态方法」
        特点：
            方法不需要第一个参数 self
            不访问实例属性、不访问类属性
            通过「类名.方法」或「实例.方法」都能调用
            属于类本身，和实例无关
        调用示例：
            Animal._make_sound()

        关键区别：能访问什么？
            ✅ 实例方法 (self)：能读 / 改 实例属性 + 类属性
            ✅ 类方法 (cls)：能读 / 改 类属性
            ❌ 静态方法：只能用传入参数，不能用 self /cls

        什么时候用 @staticmethod？
        满足以下场景就用：
            1. 方法逻辑和实例无关
            2. 不需要操作 self 实例数据
            3. 只是一个工具函数、通用计算、数据校验
            4. 想把工具方法收纳在类里面，方便管理
        举例：
            数值计算、格式转换、参数校验、简单工具函数

        三者极简对比（面试必背）
            类型	    装饰器	        第一个参数	访问权限
            实例方法	无	            self	    实例 + 类
            类方法	@classmethod	cls	        仅类
            静态方法	@staticmethod	无	        都不能，纯工具

        @staticmethod 就是：
            写在类里面的普通独立函数，
            不用 self，不依赖对象，纯工具方法

2.3 属性装饰器（@property）的高级应用
    Python 提供 @property 装饰器实现更优雅的封装，它允许我们以属性的方式访问方法，提供了一种更 Pythonic 的 getter 和 setter 实现方式。

    2.3.1 @property 基本用法
        使用 @property 装饰器可以将一个方法转换为只读属性：
            Circle.py

        @property = 把 方法 伪装成 属性
            写的是函数 / 方法
            但调用时不用加括号 ()
            像访问变量一样直接用：obj.方法名

        作用：
            定义一个只读属性
            外部可以用：circle.radius
            不能修改：circle.radius = 10 会报错！
            AttributeError: can't set attribute

        重点：
            直径、面积不是提前存好的变量
            每次访问时实时计算
            但用起来像普通属性一样简单

        对比：
        不加 @property（原始写法）
            def get_area(self):
                return 3.14 * self._radius **2
            # 调用
            circle.get_area()  # 要加括号

        加 @property（优雅写法）
            @property
            def area(self):
                return 3.14 * self._radius**2
            # 调用
            circle.area  # 不用括号！像变量一样

        @property 三大好处（必须记住）
            1. 代码更优雅
                area 比 get_area() 好看太多
            2. 实现只读属性
                外部只能读，不能改circle.radius = 20 直接报错
            3. 封装动态计算
                内部怎么算都行，外部只管像用变量一样用

        @property = 让方法看起来像属性，优雅、安全、简洁、只读。

    2.3.2 带 Setter 的属性
        通过 @属性名.setter 装饰器，可以为属性添加设置功能，实现完整的 getter 和 setter：
            Temperature.py
        属性封装 + 数据校验 结合「读 + 写 + 校验」
        1. @property → 只读 getter：取值
        2. @celsius.setter → 可写 setter：赋值、做校验

        四大核心优势
        1. 隐藏内部变量
            外部不碰 _celsius，只操作 celsius，封装性强。
        3. 读写分离
            celsius：可读可写
            fahrenheit：只读，防止篡改
        4. 动态计算
            华氏度不需要存，实时换算，数据一致。

        property → 查（get）
        @变量名.setter → 改（set）
        真实数据存在 _私有变量
        所有赋值走 setter，统一校验逻辑

        @property → 读属性（getter）
        @celsius.setter → 写属性（setter）
        赋值自动进 setter
        取值自动进 getter
        真正数据存在 _私有变量
        外部只能通过安全接口访问

    2.3.3 属性删除器
        通过 @属性名.deleter 装饰器，可以定义删除属性时的行为：
            Config.py (配置)
        区别：普通 del self._value 是彻底删掉变量；
        本例是软删除：清空内容、保留字段。

        知识点：
            1. deleter 必须绑定在已有的 property 上
                必须写 @value.deleter，不能乱写名字；
            2. deleter 方法只有 self 一个参数；
            3. 可以自由定制删除逻辑：
                软删除（赋值为 None）
                硬删除（del self._value），修改为硬删除仅需要将 self._value = None 改为 del self._value
                加权限校验、抛异常禁止删除
            4. 本例没有写 setter
                所以：
                ✅ 可读 config.value
                ✅ 可删 del config.value
                ❌ 不可改 config.value = 10 会报错

        补充：
            del 对象.属性 → 自动执行 @xxx.deleter
            用来自定义删除行为，不是单纯删变量
            真实数据存在 _xxx，deleter 操作内部私有变量
            property/setter/deleter 组成完整属性控制体系

    2.3.4 计算属性
        @property 装饰器特别适合实现计算属性，这些属性的值是基于其他属性计算得出的：
            Rectangle.py


3. 实战项目：银行账户管理系统
    3.1 项目需求分析与设计
        账户管理功能：
            - 创建不同类型的账户（储蓄账户、支票账户、高级账户）
            - 删除账户
            - 查询账户信息
            - 修改账户属性

        交易功能：
            - 存款
            - 取款
            - 转账
            - 计算利息

        账户特性：
            - 储蓄账户：最低余额要求，固定利率
            - 支票账户：透支额度，交易手续费
            - 高级账户：更高利率，奖励积分，免手续费

    3.2 系统架构设计
        系统采用分层架构设计，包含以下主要组件：

        抽象基类层：
            - BankAccount：银行账户抽象基类，定义所有账户的公共接口

        具体账户层：
            - SavingsAccount：储蓄账户类
            - CheckingAccount：支票账户类
            - PremiumAccount：高级账户类（继承自储蓄账户）

        银行管理层：
            - Bank：银行类，管理所有账户

        异常处理层：
            - 自定义异常类处理各种错误情况

        Bank_Account_Management_System

        补充：
            一、文件名规则（必须记住）
                1. 全小写
                2. 单词之间用下划线分隔（snake_case）
                3. 不要用大写、不要用横线、不要用中文、不要空格
                4. 文件名尽量和类名对应（见名知意）

            二、超级直观对照
                类名（大驼峰） | 文件名（小写 + 下划线）
                User → user.py
                UserProfile → user_profile.py
                DataExtractor → data_extractor.py
                AuthenticationMiddleware → authentication_middleware.py
                Circle → circle.py
                Temperature → temperature.py
                Config → config.py

            PEP 8 标准（Python 官方代码规范）：
                模块（就是 .py 文件）用 snake_case
                    user_info.py data_parser.py
                类用 CamelCase（大驼峰）
                    UserInfo DataParser

            最实用的 3 条铁律
                1. 一个文件放一个主要类user.py 里就写 class User:
                2. 文件名 = 类名全小写 + 下划线分隔HttpClient → http_client.py
                3.  绝对不要用中文、空格、大写、特殊符号

            类名大驼峰，文件名小写下划线，文件名对应类名

        补充2：
            关于 _next_id 准换为字符串
            现实开发中，3 个必写理由：
                1. 账号不会用来计算
                    账号只是标识，不会加减乘除→ 用字符串更合理
                2. 避免前导零丢失
                    如果账号是 001234数字会变成 1234（丢 0）字符串 "001234" 会完整保留
                3. 方便拼接、查询、接口传输
                    数据库、API、日志里，账号几乎都是字符串类型

            str(...) 就是：
                把自增的数字账号，变成字符串格式保存！
                这是工程规范，不是语法强制要求，但非常标准、非常专业。

            _next_id 全局统一计数，所有账户共用同一个自增计数器，所以应该是类变量不是实例变量
                类变量：写在类里、__init__ 外面
                    属于「整个类」，所有对象共享一份
                实例变量：写在 __init__ 里、self.xxx
                    属于「单个对象」，每个对象单独一份

                类变量：存在 类的命名空间所有实例共享、修改的是同一个值
                实例变量：存在 每个 self 实例自己的 dict 互相隔离、互不影响

            就算你写成类变量，尽量写：
                BankAccount._next_id += 1
                直接用类名。类变量，语义明确、安全

            1. 需全局共享、统一计数 → 用 类变量
            2. 需每个对象独立数据（余额、户主）→ 用 实例变量
            3. 账号自增、订单号自增、全局配置，全都是类变量场景
