面向对象编程（OOP）总结

    1. 面向对象编程基础概念
        1.1 类与对象的定义及关系
            面向对象编程（Object-Oriented Programming, OOP）是一种基于 "对象" 概念的编程范式，
            它将数据（属性）和操作数据的方法（行为）封装在一个单元中，通过对象之间的交互来实现程序功能。

                类（Class）：是对象的蓝图或模板，定义了一类对象的共同特征和行为。类是一个抽象概念，它不包含实际的数据。
                    例如，"汽车" 可以被定义为一个类，它包含了所有汽车共有的属性（如品牌、型号、颜色）和方法（如启动、加速、刹车）。
                对象（Object）：是类的具体实例，是根据类创建出来的具体实体。对象具有类定义的属性和方法，但拥有具体的属性值。
                    例如，"我的红色宝马汽车" 就是 "汽车" 类的一个具体对象，它具有特定的品牌（宝马）、颜色（红色）等具体属性。

            类与对象的关系可以用一个形象的比喻来说明：类就像是一张设计图纸，而对象则是根据这张图纸制造出来的具体产品。
            你可以根据同一张设计图纸制造出多个产品，每个产品都具有相同的基本结构，但可能有不同的外观和配置。

            在 Python 中，使用class关键字来定义类：
                class Dog:
                    pass  # 空类定义

            创建对象（实例化）的方式是调用类名并添加括号：
                my_dog = Dog()  # 创建Dog类的一个对象
                another_dog = Dog()  # 创建另一个Dog类的对象

        1.2 实例属性与类属性
            在 Python 类中，属性分为两种类型：实例属性和类属性。
            实例属性是每个对象独有的属性，它们在__init__方法中通过self关键字定义。实例属性的值在不同对象之间可以不同。
                class person

            类属性是所有对象共享的属性，它们定义在类中但在任何方法之外。类属性属于类本身，而不是单个对象。
                class person2

        1.3 实例方法、类方法与静态方法

            在 Python 类中，方法也分为三种类型：实例方法、类方法和静态方法。

            实例方法是最常见的方法类型，它只能通过对象调用，第一个参数必须是self，代表当前对象本身。
                实例方法可以访问实例属性和类属性。
                    class person3

            类方法使用@classmethod装饰器定义，第一个参数是cls，代表类本身。
                类方法可以访问类属性，但不能访问实例属性。
                    class person4

            静态方法使用@staticmethod装饰器定义，它既不需要self参数也不需要cls参数。
                静态方法不能访问实例属性和类属性，通常用于与类相关但不依赖于类状态的功能。
                    class MathUtils

            三种方法的对比总结：
                方法类型	装饰器          	第一个参数	访问实例属性	访问类属性	调用方式
                实例方法	无            	self 	    可以    	    可以   	    对象.方法()
                类方法 	@classmethod 	cls  	    不可以   	可以   	    类.方法() 或对象.方法()
                静态方法	@staticmethod	无    	    不可以   	不可以  	    类.方法() 或对象.方法()


    2. OOP 四大核心特性详解
        2.1 封装（Encapsulation）
            封装是 OOP 的核心特性之一，它指的是将数据和操作数据的方法捆绑在一个独立的单元（类）中，并隐藏对象的内部细节，只对外提供必要的接口。
            封装的核心思想是 "把该隐藏的隐藏，该暴露的暴露"。
            对象的属性（尤其是核心属性）不应该被外部直接修改，而是通过类提供的方法（getter/setter）来访问和修改，这样可以在方法中添加校验逻辑，确保数据的合法性。
            在 Python 中，封装通过命名约定实现，主要有三种访问级别：
                1. 公有成员：没有特殊前缀，可以在任何地方访问
                    class BankAccount
                2. 保护成员：以单下划线开头（如_name），表示仅供类内部或子类使用
                    class BankAccount2
                3. 私有成员：以双下划线开头（如__name），通过名称重整机制实现访问限制
                    class BankAccount3
                    Python 的私有成员通过名称重整（name mangling）机制实现，__balance实际上会被重命名为_BankAccount__balance，
                    但这种方式不应该被依赖或使用。

        2.2 继承（Inheritance）
            继承是 OOP 的第二个核心特性，它允许一个类（子类）继承另一个类（父类）的属性和方法，从而实现代码的复用和扩展。
            在继承关系中，子类可以继承父类的所有公有和保护成员，但不能继承私有成员。
            子类还可以添加自己的属性和方法，或者重写父类的方法。
                单继承示例
                    class Animal

        2.3 多态（Polymorphism）
            多态是 OOP 的第三个核心特性，它允许不同类的对象对同一方法调用做出不同的响应。多态的本质是 "同一接口，不同实现"。
            在 Python 中，多态主要通过两种方式实现：
                1. 基于继承的多态：子类重写父类方法
                    class Shape
                        Circle和Rectangle都继承自Shape类，并各自实现了area()方法。
                        当遍历shapes列表并调用area()方法时，Python 会根据对象的实际类型调用相应的area()方法，这就是多态的体现。
                2. 鸭子类型（Duck Typing）：基于对象的行为而非类型
                    class Duck
                        鸭子类型的核心思想是 "如果它走起来像鸭子，叫起来像鸭子，那么它就是鸭子"。
                        在 Python 中，我们不关心对象的类型，只关心对象是否具有所需的方法或属性。
                        Duck、Goose和Robot三个类没有任何继承关系，但它们都实现了quack()方法。
                        当调用make_quack()函数时，Python 不检查对象的类型，只要对象有quack()方法就可以正常调用。
                3. 结构化子类型（协议与抽象基类）
                    结构化子类型通过协议（Protocol）与抽象基类（Abstract Base Class，ABC）实现，提供更强的契约与校验。
                    Protocol（typing.Protocol）从静态类型角度定义 "只要实现这些成员即视为满足协议"，而 ABC 从运行时角度强制子类实现抽象方法。
                        ABC.py
                    统一支付接口 + 多种支付方式（信用卡、PayPal）
                    不管用什么支付，调用同一个方法，自动执行对应逻辑 → 这就是多态！

                (方法 3 是在 2 的基础上做了一些优化)
                (STD2\基础知识.txt 有第三种 结构化子类型（协议与抽象基类），有示例代码，此处对上述两个类型做补充)

        2.4 抽象（Abstraction）
            抽象是 OOP 的第四个核心特性，它指的是隐藏复杂的实现细节，只向外界暴露必要的接口和功能。抽象的目的是简化复杂现实，只关注相关特性。
            在 Python 中，抽象主要通过抽象基类（Abstract Base Class, ABC）来实现。
            抽象基类不能被直接实例化，它的作用是定义一组必须由子类实现的方法，从而确保接口的一致性。
                使用abc模块创建抽象基类：
                    class Payment(ABC)
                Payment是一个抽象基类，它定义了两个抽象方法process_payment和refund。
                所有继承自Payment的子类都必须实现这两个方法，否则会抛出TypeError异常。

                抽象基类的特点：
                    - 不能被直接实例化
                    - 可以包含抽象方法和具体方法
                    - 子类必须实现所有抽象方法
                    - 使用@abstractmethod装饰器标记抽象方法

        2.5 魔术方法（Magic Methods）
            魔术方法（也称特殊方法）是 Python 类中以双下划线开头和结尾的方法，它们用于实现类的特殊行为和操作符重载。
            常见的魔术方法包括：
                构造和初始化方法：
                    - __init__(self, ...)：初始化方法（构造方法）
                    - __new__(cls, ...)：创建对象的方法
                    - __del__(self)：析构方法（对象被销毁时调用）
                字符串表示方法：
                    - __str__(self)：返回对象的字符串表示（供用户查看）
                    - __repr__(self)：返回对象的官方字符串表示（供开发者查看）
                数学运算方法：
                    - __add__(self, other)：加法运算（+）
                    - __sub__(self, other)：减法运算（-）
                    - __mul__(self, other)：乘法运算（*）
                    - __truediv__(self, other)：除法运算（/）
                比较方法：
                    - __eq__(self, other)：等于（==）
                    - __ne__(self, other)：不等于（!=）
                    - __lt__(self, other)：小于（<）
                    - __gt__(self, other)：大于（>）
                容器相关方法：
                    - __len__(self)：返回容器长度（len () 函数）
                    - __getitem__(self, key)：获取元素（通过索引或键访问）
                    - __setitem__(self, key, value)：设置元素
                    - __delitem__(self, key)：删除元素
                可调用对象方法：
                    - __call__(self, *args, **kwargs)：使对象可调用（像函数一样调用）

                class Point

            补充：
                __repr__ 是 Python 内置魔法方法。
                作用：定义「对象被直接打印时」的输出内容。
                def __repr__(self):
                    # 建议格式：类名(属性1, 属性2...)
                    return f"BankAccount(holder='{self.account_holder}', balance={self._balance})"
                # 调用
                acc = BankAccount("Alice", 1000)
                print(acc)
                # 输出
                BankAccount(holder='Alice', balance=1000)

                关键知识点：
                1. 必须返回字符串
                2. 方法名：前后双下划线
                3. 自动触发场景：
                    - print(对象)
                    - 直接在控制台输入对象名回车
                    - 列表 / 容器里打印对象

                __repr__ vs __str__（简单区分）
                    __repr__：给开发者看，偏向代码风格、精准还原
                    __str__：给用户看，偏向简洁友好
                    只写 __repr__ 时，print 会自动用它兜底

                极简固定模板（直接套用）：
                    def __repr__(self):
                        return f"类名(属性1={xxx}, 属性2={xxx})"


    3. Python OOP 高级特性
        3.1 属性装饰器（@property）
            Python 的@property装饰器是一个强大的工具，它将类的方法转换为属性，使得方法可以像普通属性一样被访问和赋值，
            同时支持在访问 / 赋值时添加自定义逻辑。

            1. 基本用法 - 只读属性：
                class Circle
                diameter和area都是只读属性，它们的值是基于radius动态计算的。用户可以像访问普通属性一样访问它们，但不能直接修改。
            2. 带 Setter 的属性:
                通过@属性名.setter装饰器，可以为属性添加设置功能：
                    class Temperature
                在celsius的 setter 方法中，添加了数据验证逻辑，确保温度值不会低于绝对零度。
            3. 属性删除器：
                通过@属性名.deleter装饰器，可以定义删除属性时的行为：
                    class Config

        3.2 组合与委托
            组合（Composition） 是一种设计原则，它强调通过组合简单对象来构建复杂对象，而不是通过继承创建类层次结构。
            组合体现的是 "has-a"（有一个）关系，而继承体现的是 "is-a"（是一个）关系。

            组合的优势：
                - 比继承更加灵活，不会形成僵化的继承链
                - 支持运行时动态改变对象的行为
                - 遵循单一职责原则，每个类都有明确的职责

            组合示例：
                class Engine
            Car类包含（组合）了一个Engine对象，通过委托（delegation）的方式让Engine对象处理启动和停止操作。

            委托（Delegation）是指一个对象将某些操作委托给另一个对象来处理。在上面的例子中，Car的start()方法委托给Engine的start()方法。

        3.3 设计模式应用
            设计模式是在软件开发中反复出现的问题的通用解决方案。Python 由于其动态特性，使得许多设计模式的实现更加简洁和优雅。

            工厂模式（Factory Pattern）：
                工厂模式提供了一种创建对象的方式，而无需指定具体的类。它通过定义一个工厂类来封装对象的创建逻辑，从而降低耦合度。
                    class Animal

                补充：
                    1. 继承只在 class 定义时声明：class Dog(Animal)
                    2. 后续所有代码里，只用写 Dog、Cat 类名
                    3. 工厂字典存「类」，后面加 () 就能造子类对象
                    4. 所有 Dog/Cat 实例，天然都是 Animal 子类类型

                    Animals 中 Dog 是类本身,不是写继承、不是写 Dog(Animal)
                    继承只能写在「类定义」的地方
                        # 这里才是写继承的地方！
                        class Dog(Animal):
                            pass

                        class Cat(Animal):
                            pass
                    只要上面这么写了：
                        👉 Dog 天然就是 Animal 的子类
                        👉 Cat 天然就是 Animal 的子类
                    字典里不需要、也不能再写一遍继承

                    "dog": Dog
                        - Dog 👉 代表整个类
                        - Dog() 👉 才是创建对象
                        cls = Dog       # 拿到类
                        obj = Dog()     # 调用类，造实例

            单例模式（Singleton Pattern）：
                单例模式确保一个类在整个程序运行过程中只创建一个实例对象，无论调用多少次类的构造方法，返回的都是同一个实例。
                    class Singleton

                补充：
                    使用装饰器
                        @singleton
                        class DatabaseConnection:
                            ...
                    等价于
                        DatabaseConnection = singleton(DatabaseConnection)
                        之后调用 DatabaseConnection() 实际调用的是装饰器里的 get_instance

                    更严谨的加锁的版本中，字典的键为一个元组，因为元组是不可变的所以符合字典键的规定，
                    元组的内容为，类名、位置参数和一个存放在元组中排序后的关键字参数的键值对
                        - sorted()：保证 name="a", age=18 和 age=18, name="a" 被视为同一个 key
                        - tuple()：把列表变成不可变类型，才能放进 key 里

                    修改后的逻辑就是：【类 + 传进去的所有参数】完全一样，才返回同一个实例。

            观察者模式（Observer Pattern）：
                观察者模式定义了对象之间的一对多依赖关系，当一个对象（主题）的状态发生变化时，所有依赖于它的对象（观察者）都会得到通知并自动更新。
                    class Subject

        3.4 元类（Metaclasses）
            元类（Metaclass）是创建类的类，它定义了类的创建过程。在 Python 中，所有的类都是type类的实例，而type本身就是一个元类。
            使用元类可以：
                - 自动注册类
                - 强制类遵循特定的编码规范
                - 创建领域特定语言（DSL）
                - 在类创建时动态修改类

                class MyMeta
            MyMeta元类在创建MyClass时自动添加了created_by属性。
            元类的__new__方法接收以下参数：
                - cls：元类本身 MyMeta
                - name：要创建的类名（这里是 MyClass）
                - bases：父类元组
                - attrs：类的属性 / 方法字典（一开始是空的）
            核心逻辑：强行给类的属性字典添加一个 created_by 属性，所有用这个元类创建的类，都会自带这个属性。
            最后调用父类 type 的 __new__ 完成类的创建，可以不用，如果类继承自type。

            元类 = 类的类
                - 对象是由类创建的
                - 类是由元类创建的
            定义 MyClass → 触发 MyMeta.__new__ → 自动添加属性 → 创建完成 MyClass

            元类能做什么？
            这个例子只是最基础的演示，元类还可以：
                - 自动给所有子类添加方法 / 属性
                - 检查类的定义是否符合规范（比如必须实现某个方法）
                - 注册类到全局管理器
                - 实现 ORM 框架、单例模式等高级功能
