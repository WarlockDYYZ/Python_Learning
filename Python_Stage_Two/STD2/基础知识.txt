Python 多态与封装

1. 多态基础理论与实践
1.1 多态概念与核心价值
    多态（Polymorphism）是面向对象编程的三大核心特性(继承、封装、多态)之一，源于希腊语，意为 "多种形态"。
    在面向对象编程中，多态指的是不同的对象可以对同一消息做出不同的响应，简单来说就是相同的方法调用在不同的对象上可能会产生不同的行为。

    多态的核心价值体现在三个方面：
        提高代码的灵活性
            多态允许我们编写通用的代码，这些代码可以处理不同类型的对象，而不需要为每种对象类型编写特定的代码。
            这样，当需要处理新的对象类型时，只需要确保该对象实现了所需的方法，就可以直接使用现有的代码。
        增强代码的可扩展性
            在软件系统中，随着需求的变化，可能会不断添加新的对象类型。多态使得我们可以轻松地扩展系统，而不需要对现有的代码进行大规模的修改。
            只需要为新的对象类型实现相应的方法，就可以将其集成到系统中。
        实现代码的复用
            通过多态，我们可以将通用的逻辑封装在一个函数或方法中，然后让不同的对象调用这个函数或方法，从而实现代码的复用。


1.2 多态的类型与实现机制
    在 Python 中，多态主要有三种实现方式：
    1. 基于继承的多态（子类型多态）
        基于继承的多态是最经典的 OOP 方式，通过子类重写父类方法实现。
        当子类继承父类并重写方法时，调用统一接口可获得具体子类的差异化行为，这直接体现了里氏替换原则（LSP）：所有子类，必须能够完全替换掉父类，且程序功能不受影响。

        实现基于继承的多态需要满足三个条件：
            1. 必须存在继承关系，有父类有子类
            2. 子类必须重写父类的某个方法，即子类中有一个和父类同名的方法，但具体实现不同
            3. 调用时需要使用父类类型的引用，实际传的是子类的对象
        Animal.py
    2. 鸭子类型（动态多态）
        鸭子类型（Duck Typing）是 Python 多态的精髓，它强调 "看行为而非看血统"，即对象只要提供所需属性或方法，就被视为可用。
        Python 的多态不依赖于继承（虽然继承是实现多态的一种方式），而是依赖于接口的非正式协议。

        鸭子类型的哲学是："如果它走起来像鸭子，叫起来像鸭子，那么它就可以被当作鸭子来对待"。
        在 Python 中，只要一个对象实现了所需的方法，就可以在需要该方法的地方使用它，而不需要考虑对象的具体类型。
        Duck.py

        补充：
        静态语言 vs Python 区别
        1. Java/C++（静态多态）
            必须严格继承父类 / 实现接口
            类型编译期检查，父子类关系强绑定
            是「血统绑定」：是不是子类，才决定能不能用
        2. Python（鸭子类型・动态多态）
            没有强制继承
            运行时动态检查：只要有对应方法，就能调用
            是「行为绑定」：不管你是谁，能干这件事就行

            和多态的关系
                1. 传统多态（静态）父类 → 子类 重写方法，依靠继承实现。
                2. 鸭子类型（动态多态）不需要父类，只要方法名一致，天然实现多态。Python 的多态，本质就是鸭子类型支撑的动态多态。

            优点
                代码灵活、轻量化，不用写冗余父类 / 接口
                低耦合，类之间不用强继承绑定
                快速开发，适配性极强
            缺点
                无编译检查，写错方法名运行才报错
                代码可读性变差，看不到统一规范
                容易出现隐式 Bug

            Python3.8+ 提供 typing.Protocol既保留鸭子类型的灵活，又能做类型提示、规范方法：
                依然不强制继承
                但统一约束「必须具备哪些方法」
            Dog_And_Cat.py
            加了 Protocol：
                保留灵活
                有标准
                有代码提示
                有类型检查
            👉 这就是 Python 最优雅的 “接口” 方案！
        3. 结构化子类型（协议与抽象基类）
            结构化子类型通过协议（Protocol）与抽象基类（Abstract Base Class，ABC）实现，提供更强的契约与校验。
            Protocol（typing.Protocol）从静态类型角度定义 "只要实现这些成员即视为满足协议"，而 ABC 从运行时角度强制子类实现抽象方法。
            ABC.py
            统一支付接口 + 多种支付方式（信用卡、PayPal）
            不管用什么支付，调用同一个方法，自动执行对应逻辑 → 这就是多态！


1.3 多态在实际项目中的应用场景
    场景 1：数据处理管道
    假设你需要处理来自 API 的 JSON 数据、数据库查询结果和 CSV 文件内容，它们的结构各不相同，但最终都需要提取 user_id 字段。
    使用多态可以实现统一处理：
        extract_user_id.py

        同一个函数 process_data()
        同一个方法名 extract_user_id()
        不同来源的数据 JSON、数据库、CSV
        自动正确执行
        → 这就是多态！

    这种写法的好处（超级重要）
        统一接口外面调用永远只需要记 extract_user_id()
        易扩展加新的提取方式（Excel、API…），只要新建子类，不改动旧代码
        易维护逻辑分散在各自子类，不乱
        符合开闭原则对扩展开放，对修改关闭

    场景 2：策略模式
    电商系统中需要根据用户等级（普通 / VIP / 钻石）计算不同的折扣。使用多态可以轻松实现策略切换(折扣策略)：
        DiscountStrategy.py
        道理都是类似的，代码我看得懂

    场景 3：Web 框架中间件系统
    Django 的中间件机制就是多态的典型应用。每个中间件只需实现__call__方法，就能拦截请求 / 响应进行处理：
        Web_Middleware.py
