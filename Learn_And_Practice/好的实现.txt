has_subset_sum

虽然它没有使用传统的二维数组（如 dp[i][j]），但它完美地诠释了动态规划解决问题的底层逻辑。
(之前学0-1背包问题的时候，使用的是二维数组dp，还手动推到过dp的内容)

1. 状态的定义 (State Definition)
    在动态规划中，我们首先要明确“状态”是什么。
    在这段代码里，possible_sums 这个集合就是状态容器。
        - 它记录了在遍历到当前数字时，前面的数字“能够凑出的所有和”。
        - 比如 possible_sums = {0, 2000, 3000} 就代表：用目前手里的牌，我可以凑出 0、2000 或 3000 这三种结果。

2. 状态转移 (State Transition)
    这是动态规划的灵魂，即“如何利用旧状态推导出新状态”。
    代码中的双重循环正是状态转移的过程

    逻辑是：对于每一个已经能凑出的旧和（current_sum），面对当前新来的数字 num，我们都有两个选择：
        - 不选 num：保持原来的 current_sum 不变。
        - 选 num：产生一个新的和 new_sum = current_sum + num。
                通过这种“旧状态 + 新决策 = 新状态”的方式，我们一步步把问题的规模扩大。

3. 初始状态 (Base Case / Initialization)
    动态规划必须有一个明确的起点。
        possible_sums = {0}  # 初始状态：和为 0 总是可以凑出来的（什么都不选）
    这行代码就是边界条件。它定义了在没有遍历任何数字之前，我们唯一能确定的事实就是“凑出和为 0”（即什么数字都不拿）。
    所有的后续状态都是基于这个 {0} 像滚雪球一样推导出来的。

4. 避免状态覆盖 (Handling State Overlap)
    这是这段代码中最精妙、也最体现 DP 严谨性的地方：
        new_sums = set()
        # ... 在 new_sums 中计算新产生的和 ...
        possible_sums.update(new_sums)

    在经典的动态规划数组解法中，为了防止“这一轮的新状态”干扰“这一轮的旧状态计算”，我们通常会采用倒序遍历（从 target 往 0 遍历）。
    而在这里，通过引入一个临时的 new_sums 集合，先把新产生的和存起来，等这一轮全部算完后，
    再一次性合并（update）回主集合 possible_sums。
    这完美地保证了在推导新状态时，依赖的永远是上一轮完整且未被修改的旧状态，避免了数据的错乱。

总结一下：
    这段代码用集合（Set）代替了传统的布尔数组（dp[j] = True/False），用“暂存再合并”代替了“倒序遍历”。
    虽然形式不同，但它严格遵循了动态规划“定义状态 -> 设定初始值 -> 推导状态转移 -> 避免状态污染”的标准范式。
